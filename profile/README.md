# IDM-GitSpace 利用ルールブック（ガイドライン）

本ドキュメントは、当社のGitHub Free for Organizationsを用いた開発を安全かつ円滑に進めるためのルールを定めたものです。
Organizationに参加するすべてのメンバーは、本ルールを熟読し、遵守して開発を行ってください。

## 1. アカウント・セキュリティルール

管理者がアクセス権限を適切に制御し、情報漏洩やセキュリティ事故を防ぐための基本ルールです。

* **2要素認証（2FA）の必須化**
  * Organizationに参加するすべての個人アカウントに対し、2要素認証（認証アプリ、SMS、セキュリティキー等）の設定を必須とします。
* **アカウントとメンバー権限の管理**
  * オーナー（Owner）権限を持つ管理者は必要最小限とし、開発メンバーには原則として `Member` 権限および対象リポジトリの `Write`（メイン開発者は `Maintain`）権限を付与します。
* **メンバー離脱時の対応手順**
  * プロジェクト離脱時または退職時は、管理者が速やかにOrganizationから該当の個人アカウントを除外し、アクセス権限を削除します。

## 2. ローカル環境・機密情報管理ルール

本プロジェクトでは個人所有のPCをローカル開発環境として利用するため、特にデータ管理を厳重に行います。

* **機密情報・パスワード等のコミット厳禁**
  * APIキー、パスワード、接続文字列、個人情報などの機密情報は、絶対にソースコード内に直接記述してコミット・Pushしないでください。
  * 設定ファイルなどは `.gitignore` で除外し、環境変数やローカル専用の設定ファイルを利用してください。
* **ソースコードのローカル放置禁止・こまめなPush**
  * PCの紛失や故障、データ破損リスクに備え、作業の区切り（キリの良いタイミング）ごとにこまめに自社リポジトリへPushを行ってください。
* **プロジェクト離脱時のローカルデータ廃棄義務**
  * 開発体制から外れる際は、個人PC上のローカルリポジトリ（クローンしたソースコード等のデータ一式）を完全に削除・破棄することを義務付けます。

## 3. リポジトリ・ブランチ運用ルール

チーム開発において、ソースコードの競合や先祖返りを防ぎ、品質を保つための運用ルールです。

* **ブランチ運用方針（基本戦略）**
  * `main`（または `master`）：本番・リリース用ブランチ。常にデプロイ可能な状態を保ちます。
  * `develop`：開発統合用ブランチ。機能開発が完了したコードをここに集約します。
  * `feature/〇〇`：各タスク・機能開発用のブランチ。作業開始時に `develop` から切り出します。
* **ブランチ保護設定（Branch Protection）**
  * `main`への直接Push（直コミット）は禁止します。必ずプルリクエスト（PR）を作成し、レビューを経由してマージしてください。
* **コミットメッセージ規約**
  * 変更内容が後から見て分かりやすいよう、日本語で簡潔に記述してください。
  * 推奨プレフィックス： `feat:` (新機能), `fix:` (バグ修正), `docs:` (ドキュメント変更), `refactor:` (リファクタリング)

## 4. プルリクエスト（PR）・コードレビュー運用

タスクの進行状況を可視化し、チーム全体でコード品質を高めるためのルールです。

* **タスク・Issue管理**
  * 作業単位ごとに GitHub Issues を作成し、担当者をアサインして進行管理を行います。PR作成時は、関連するIssueを紐付けてください。
* **レビューフロー**
  * PRを作成したら、レビュアーを指定してコードレビューを依頼します。
  * 指定されたレビュアーの承認（Approve）を受けてから、管理者（またはリポジトリ作成者）がマージを実施します。
* **CI/自動チェック**
  * GitHub Actions等によるビルドチェックや自動テストが設定されている場合、それらのチェックをすべて通過することをマージの必須条件とします。
